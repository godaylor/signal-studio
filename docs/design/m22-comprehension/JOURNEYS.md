## Основной вывод

В приложении уже есть настоящий аналитический цикл: события → запрос → результат
→ сохранённый анализ → дашборд → профиль/сессия → экспорт. Главная проблема
понятности — недостаток связи между вопросом, определением показателя и следующим
действием. Технические названия и пустые состояния требуют знания устройства
аналитики. Избыточная анимация сама по себе эту проблему не решает.

## Остальные ограничения исходного интерфейса

Эти пункты подтверждены исходниками, но не означают, что весь соответствующий
раздел не работает. При изменениях нужно сохранить серверные права и реальные
данные.

| Область | Наблюдение | Разумное продолжение |
| --- | --- | --- |
| Язык аналитики | В `blockValue()` Retention оставалось `week periods`, в `FilterEditor` — исходные `urlPath`, `doesNotContain` и прочие ключи; определения из `server/analytics/definitions.ts` приходили по-английски и выводились напрямую. | Понятные локализованные подписи в представлении при неизменных ключах контракта. Исходное имя события можно оставить вторичным техническим идентификатором. |
| Права на сохранённые анализы | `InsightLibrary.tsx` показывал изменение названия, звёздочку, дублирование и архивирование всем открывшим библиотеку. Сервер правильно запрещает операции через `insight-service.ts`, но интерфейс не объясняет недоступное действие заранее. | Применить capability-aware действия по образцу экспорта, не заменяя серверную проверку скрытием кнопок. |
| Прямой вход в «Опыт» | Без `sessionId` раздел предлагает сначала выбрать пользователя в другом разделе (`ExperienceWorkspace.tsx`, ветка `!sessionId`). Полезных сессий на самом входном экране нет. | Понятный переход к профилям или ограниченный список доступных сессий через существующий API. Не показывать фиктивный replay в гостевом наборе. |
| Возврат из сессии | Подпись «Назад к анализу» постоянная, хотя безопасный `returnTo` может вести в Audiences или Live; при прямом входе он по умолчанию ведёт в Audiences. | Подпись по реальному месту возврата или нейтральное «Вернуться». |
| Ошибки сессии/участников | Есть защищённые объяснения ошибок, но не во всех ветках есть локальный Retry (`ExperienceWorkspace`, `MemberDialog`, `DrilldownDialog`). | Повтор без потери применённого вопроса и выбранного участника. |
| Гостевой вход под лимитом | Все 429 сводятся к «пространства заняты, попробуйте позже» (`GuestStartButton.tsx`), хотя ограничение может быть клиентским/глобальным. | Показать доступный безопасный код/Retry-After без раскрытия других гостей; не сбрасывать лимиты ради демонстрации. |
| Визуальный Live | «Сигнал по минутам» представлен таблицей. Это правдивая и доступная форма, но не даёт быстрого зрительного чтения изменения активности. | Небольшая диаграмма из тех же `snapshot.series` с сохранением таблицы; никаких сгенерированных новых наблюдений. |
| Имена и формулы | Home показывает зрелую когорту, Explore — выбранную воронку; одинаковые проценты могут относиться к разным людям и периодам. В исходном Home объяснение 21-дневного окна есть в details. | Рядом с вопросом кратко показывать популяцию, знаменатель и период. Подробности — в справке. Не объявлять Home и произвольную воронку одной и той же метрикой. |
| Сегментированная воронка → участники | Существующий drilldown-контракт принимает шаг/outcome, но не конкретный segment, поэтому возвращает участников всех групп вместе. | M22 явно называет действие/диалог «все группы» и предлагает добавить фильтр для отдельной группы. Полноценная сегментная детализация не добавлялась; числа сравнения групп остаются независимыми. |
| Retention → экспорт | Матрица теперь отличает неполный период от итогового нуля, но исходный SQL-горизонт не расширен; экспорт содержит первоначальные частичные числа. | Ограничение прямо названо рядом с матрицей. Не считать UI maturity-метку изменением аналитического контракта CSV/JSON. |
