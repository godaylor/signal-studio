## Результат для пользователя

Сцены входа, вопроса и ответа получили согласованное появление; изменение
воронки плавно перестраивает настоящую геометрию, графики раскрывают реальные
данные, а навигация и расчёт показывают ожидание. Показатель сразу содержит
точное серверное значение: счётчика с выдуманными промежуточными числами нет.
Home проверен на **56 → 28 → 21**, пример анализа — **336 → 252 → 168**;
смена цели использует соответствующие фактические количества, включая 84 подписки.

Текст остаётся полностью непрозрачным даже во вложенных сценах: появление
использует только смещение 12 px. Движение потока означает направление,
а не новых посетителей. Оси, подписи, таблицы и действия доступны во время эффекта.
Появление ограничено 620 мс, раскрытие графика — 660 мс с ограниченным stagger;
после паузы/смены политики эффект завершается на точном целевом состоянии.

## Пять исправленных рабочих сценариев

| Было | Стало и регрессия |
| --- | --- |
| «Сбросить только фильтры» восстанавливал applied URL и стирал другие несохранённые правки. | Меняется только локальный черновик фильтров. Событие и даты сохраняются до «Выполнить анализ»; тест проверяет итоговый URL. |
| Ошибка переименования анализа закрывала редактор и теряла удобный повтор. | Редактор и название остаются после отказа PATCH; закрытие только после успеха. Пустой/повторный pending submit заблокирован; проверен успешный retry. |
| Дашборд позволял выбрать лишь первые 20 сохранённых анализов. | Явная загрузка следующей cursor-страницы по прежнему лимиту 20, loading/error/retry. Загруженные варианты сохраняются при отказе; тест выбирает анализ со второй страницы. Автоматической безграничной загрузки нет. |
| Замена DTO дашборда после заметки/виджета стирала несохранённый общий период/сегмент. | Инициализация зависит от dashboard ID и канонического applied-context значения. Ревизии правок отделены от подтверждённого сохранения; поздний ответ не стирает новый ввод, даже если пользователь вернулся к прежней дате. |
| Первичный SSR-экран показывал активный гостевой CTA до готовности JavaScript. | Кнопка disabled/busy до hydration и во время запроса. Новый тест реально удерживает JS, проверяет серверный документ и доступность после загрузки. На прежней production-сборке тест воспроизвёл enabled; на исправленной прошёл в Chrome и WebKit. |

При переключении дашборда загружается его контекст. Внешнее изменение applied
контекста обновляет нетронутый редактор, сохраняя начатый черновик. Во время
сохранения Apply/Clear защищены от повторного запроса, сами поля остаются доступны.
Тесты воспроизводят замену DTO, новый ввод при задержанном ответе и переключение.

Первый CI [39857231905](https://github.com/godaylor/signal-studio/actions/runs/39857231905)
завершился 6/6, но критическая регрессия содержала **41 first-pass + 2 retry-pass**,
а не 43 чистых прохода. Один тест не наблюдал guest POST, другой исчерпал
5-секундное ожидание URL. Артефакта первой попытки не было, поэтому связь первого
отказа с hydration остаётся выводом, а не доказанным диагнозом. Отдельно доказана
сама доступность старого CTA при удержанных скриптах и её устранение. Mixed-auth
тест теперь ждёт реальный POST200 и затем навигацию до30с; проверки токена,
изолированного доступа и результата сохранены. Последний CI фиксируется отдельно.

Первый вариант нового теста предполагал только `/_next/static/chunks/` и видимый
SSR в каждом движке. Vercel использует также `static/immutable/chunks`, а WebKit
может держать streamed HTML скрытым до скриптов. Исправлена проверка, а не ответ
приложения: удерживаются оба пути, анализируется настоящий серверный документ,
любой уже видимый CTA проверяется disabled, затем загружаются реальные скрипты.
Финальный переносимый вариант прошёл в public Chrome и native WebKit.
