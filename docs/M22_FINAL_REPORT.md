# M22 — понятный продукт и проверка адаптивности

**Статус: Complete.** Дата: 18 октября 2026, Europe/Moscow. Исходное дерево
чистое на `d8eacd5fa`. Финальная ревизия
`dff0f544d16dc724ea8d663f6d0870ed6513760c` прошла все **6/6 CI jobs**, native
build, полный публичный гостевой workflow, table-only/reload/drilldown и три
фокусных браузерных сценария. Это завершение описанного M22 scope с явно
перечисленными ниже границами, а не сертификация всех физических устройств.

Пользователь отклонил понятность M21 и расхождение imagegen-концепции с реальным
продуктом. M22 оценивает работающие экраны: понятный вопрос, объяснимые числа,
визуальные доказательства и следующий шаг. Исторические imagegen-доски обозначены
как поиск направления; они не выдаются за точную копию реализации.

## Что изменилось для пользователя

- Первый экран объясняет задачу продукта и вымышленный Orbit. Гость начинает
  с рабочего анализа; три понятных вопроса меняют обычный нормализованный запрос.
- Воронка использует реальные количества участников. Краткий вывод объясняет
  прохождение, наибольшую потерю между шагами и различие конверсии групп без
  выдуманной причины поведения. График расположен раньше подробной интерпретации
  и таблицы; служебные определения раскрываются отдельно.
- Старый ответ больше не переименовывается в результат нового вопроса во время
  запроса. Повтор того же вопроса действительно пересчитывается. Ошибки и отказ
  Clipboard API получили понятное восстановление.
- Сегмент показывает состав именно применённых условий, включая поздние ответы.
  Сохранённый сегмент можно снова исследовать. Поиск аудиторий сохраняет смысл
  при переходе назад/вперёд; пустые и ошибочные состояния предлагают действие.
- Дашборд учитывает право создания, сохраняет заметку при отказе и не стирает
  новый текст, набранный во время сохранения. Общий период и метаданные спокойнее
  отделены от чтения результатов.
- Мобильный редактор перекрывает оболочку и возвращает фокус после закрытия,
  включая WebKit pointer/touch. Узкие действия переносятся, плотные таблицы и
  длинные воронки прокручиваются локально. Короткий landscape не прячет фокус под
  нижней навигацией; на 8K действия остаются в читаемой области.

Подробный список находок и сценариев: [JOURNEYS.md](design/m22-comprehension/JOURNEYS.md).
Галерея: [REVIEW.html](design/m22-comprehension/REVIEW.html),
[до/после](design/m22-comprehension/compare.html). Финальные production-снимки
семи разделов × двух тем × двух форматов приняты на e0c: **28/28**, без document
overflow и serious/critical axe violations. Сама галерея принята при ширинах
390/1600 px: **56** переключений снимков и **4** состояния сравнения, без
overflow, JS/asset errors и serious/critical axe. Доска устройств составлена
из настоящих снимков одного вопроса; видео **10,64 с** показывает его работу.
Видео имеет controls, playsinline и текстовую альтернативу, без autoplay.

## Аналитические границы, которые сохранены

SQL, единицы анализа, identity, half-open диапазоны, фильтры и права не менялись.
Home по-прежнему использует зрелую 21-дневную когорту; его процент нельзя
приравнивать к произвольной воронке другого периода. Home получил только раннюю
остановку уже отменённого запроса, без распараллеливания тяжёлых метрик.

В Retention **не расширялся SQL-горизонт возвратов**. Интерфейс отличает неполный
календарный период от итогового нуля; взвешенная сводка использует завершённые
периоды. **CSV/JSON сохраняют исходные частичные значения**, о чём прямо сказано
рядом с матрицей. Это изменение подачи и зрелости сводки, а не миграция хранения.
Golden-проверки покрывают `[start,end)`, DST, дни, недели и месяцы.

Детализация шага сегментированной воронки по существующему контракту возвращает
участников **всех групп вместе**. Заголовок/описание диалога и действие это явно
обозначают. Для отдельной группы нужно добавить фильтр в вопрос; ссылка на
выбранный сегмент в drilldown-контракт не добавлялась. Показанное различие
конверсии групп рассчитывается с независимыми знаменателями каждой группы.

## Оставшиеся ограничения

1. Холодный Home около 11,9 с остаётся отдельной задачей. Наивное параллельное
   выполнение метрик при публичном pool2 может вызвать timeout; такой риск не
   маскируется быстрыми повторными HTTP-запросами.
2. Retention экспорт содержит исходные частичные числа; детализация
   сегментированного шага объединяет все группы. Оба ограничения названы в UI.
3. Firefox UI не проверен из-за adapter failure. WebKit не равен ручной проверке
   Safari; физические iOS/Android устройства и screen reader ещё не приняты.
4. 200 px — диагностический стресс, 7680×4320 при DPR1 — 8K CSS viewport,
   а не обещание оптимизации для любого физического экрана. 200-мегапиксельный
   framebuffer не создавался. Zoom/DPR/аспект и физические пиксели различаются.
5. Некоторые технические определения/ключи ещё доступны по-английски;
   Experience при прямом входе требует выбрать сессию через профиль. Полный
   governance-каталог, AI-причины и новые аналитические контракты не добавлялись.

Другие проекты, контейнеры, базы и volumes не удалялись и не останавливались.
